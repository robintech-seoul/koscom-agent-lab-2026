# [1-2] 문서 적재, 평가셋

- **일시:** 1일차 10:00–11:00 (강의 10분 + 실습 40분)
- **교재:** 23–33쪽 (실습은 29–32쪽)
- **결과물:** `src/ingest.py`, `src/run_eval.py`, `data/parsed/articles.jsonl`

## 이번 시간에 하는 것

규정 문서를 조항 단위로 나눠 저장하고, 조항마다 메타데이터(문서, 조항, 시행일, 보안 등급, 개정 차수)를 붙입니다. 이 메타데이터가 이후 필터, 인용, 현행성 판단의 기반이 됩니다. 그리고 모든 방식을 같은 조건으로 실행하고 기록하는 평가 러너를 만듭니다.

## 준비

- 1-1의 기준선 결과 파일(`eval/results/baseline_r1.jsonl`)

## 실습

### 실습 ① 조항 단위 적재 스크립트 (교재 29쪽)

```text
src/ingest.py를 만들어줘.
- data/raw/의 PDF·HWPX·DOCX를 파싱해 조항 단위로 분할
- 각 조항에 doc, article, effective_date, security_level, revision 메타데이터
- data/parsed/articles.jsonl로 저장
- 파싱 실패 문서와 메타데이터 누락 건수를 마지막에 출력
```

- 누락이 0건이 될 때까지 Claude Code와 함께 고칩니다.
- 조항 경계가 맞는지는 3건 이상 직접 원문과 대조합니다. Claude Code가 "누락 0건"이라고 출력해도, 실제로 조항이 제대로 나뉘었는지는 사람이 봐야 합니다.

### 실습 ② 평가셋 5건을 원문과 대조한다 (교재 30쪽)

평가셋의 정답 조항이 틀리면 이후 모든 점수가 틀립니다. `eval/questions.jsonl` 30건 중 5건을 골라 원문과 맞춰 봅니다.

평가셋 한 건의 필드 예시:

```json
{"id": "Q07", "type": "trap_revision", "question": "...", "gold_answer": "...",
 "gold_citations": [{"doc": "시세정보전송규정", "article": "제12조", "effective": "2026-03-01"}],
 "role": "general", "notes": "2025 개정 전 조항은 30초, 개정 후 15초"}
```

확인할 것:
- `gold_citations`(정답 조항)의 문서, 조항, 시행일이 원문과 같은가
- `gold_answer`(정답)가 그 조항 내용과 맞는가

### 실습 ③ 평가 러너를 만든다 (교재 31쪽)

평가 러너는 그래프 모듈이나 결과 파일을 받아 같은 형식으로 기록합니다. 이후 모든 방식을 이 러너 하나로 잽니다.

```text
src/run_eval.py를 만들어줘.
- 입력: LangGraph 그래프 모듈 경로 또는 결과 jsonl 경로
- 그래프면 평가셋 전체를 실행해 eval/results/<name>_r<n>.jsonl로 저장
- 기록 항목: 답변, 인용, 토큰, 지연
- 채점은 다음 세션에서 붙일 수 있도록 함수만 분리해 둬
- CLAUDE.md의 결과 형식을 따를 것
```

- solutions의 샘플 그래프로 러너가 동작하는지 확인합니다.
- 채점 함수는 2-1에서 붙이므로 지금은 분리만 해 둡니다.
- 기준선(Claude Code 결과)은 결과 jsonl 경로로 넣습니다.
