# 보안 사고·개인정보 유출 대응

## 보안 사고 보고
- 이용자는 보안 사고를 발견하거나 의심되는 경우 즉시 소속 부서의 장과 정보보호 담당 부서에 알려야 한다 [정보보호규정 §제13조, 시행일 2026-04-01].
- 정보보호 담당 부서는 사고 접수 후 2시간 이내에 사고의 범위와 원인을 확인하여 정보보호최고책임자에게 보고한다 [정보보호규정 §제13조, 시행일 2026-04-01].
- 정보보호최고책임자는 사고의 중대성을 판단하여 대표이사에게 보고하고 필요한 경우 관계 기관에 신고한다 [정보보호규정 §제13조, 시행일 2026-04-01].
- 사고가 수습된 뒤에는 재발 방지 대책을 수립하여 이행한다 [정보보호규정 §제13조, 시행일 2026-04-01].

## 개인정보 유출 사고
- 직원은 개인정보의 유출을 알게 되면 즉시 개인정보 보호책임자에게 알려야 한다 [개인정보처리지침 §제11조, 시행일 2026-01-01].
- 개인정보 보호책임자는 유출 사실을 안 때부터 72시간 이내에 해당 정보주체에게 통지한다 [개인정보처리지침 §제11조, 시행일 2026-01-01].
- 유출 규모가 법령에서 정한 기준 이상인 경우에는 관계 기관에 신고한다 [개인정보처리지침 §제11조, 시행일 2026-01-01].
- 유출 사고의 원인과 조치 내용은 사고 대장에 기록한다 [개인정보처리지침 §제11조, 시행일 2026-01-01].

## 접속 기록과 점검
- 접속 기록은 변조되지 않도록 별도의 저장 공간에 보관하며 보관 기간은 1년이다 [정보보호규정 §제12조, 시행일 2026-04-01].
- 정보보호 담당 부서는 접속 기록을 분기마다 점검하여 비정상적인 접근이 있는지 확인한다 [정보보호규정 §제12조, 시행일 2026-04-01].
- 개인정보 보호책임자는 이 지침의 이행 상황을 반기마다 점검하고 결과를 경영진에 보고한다 [개인정보처리지침 §제12조, 시행일 2026-01-01].

## API 키 관리
- API 키는 키 관리 시스템 KMS-2에 보관하며 소스코드 저장을 금지한다 [정보보호규정 §제14조, 시행일 2026-04-01].
- API 키가 노출되었거나 노출이 의심되는 경우에는 즉시 폐기하고 새 키를 발급한다 [정보보호규정 §제14조, 시행일 2026-04-01].
- 정보보호 담당 부서는 소스코드 저장소에 API 키가 포함되어 있는지 분기마다 점검한다 [정보보호규정 §제14조, 시행일 2026-04-01].
