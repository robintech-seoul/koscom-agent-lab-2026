## 실습

### 실습 ① 질문 1건으로 먼저 확인하기 (교재 19쪽)

Claude Code에 아래 지시문을 그대로 입력합니다.

```text
data/regs_all.md 전체를 읽고, 그 내용만 근거로 다음 질문에 답해줘.
다른 파일은 열지 마. 답에는 문서명·조항·시행일을 인용해.
질문: 시세 전송 지연 시 참가사 통보 기준은?
```

확인할 것:
- 답에 문서명, 조항, 시행일이 붙었는가
- `data/regs_all.md` 외에 다른 파일을 열지 않았는가

### 실습 ② 평가셋 30건을 한 번에 실행하기 (교재 20쪽)

30건을 하나씩 입력하지 않고 스크립트로 실행합니다. 그래야 이후 다른 방식과 같은 조건으로 비교할 수 있습니다. 헤드리스 모드(`claude -p`)는 Claude Code를 대화 화면 없이 명령 한 줄로 실행하는 방식입니다.

```text
scripts/run_claude_baseline.sh 를 만들어줘.
- eval/questions.jsonl의 각 질문에 대해 claude -p를 호출
- 도구는 Read만 허용, 읽을 파일은 data/regs_all.md 하나
- --output-format json 결과에서 답변·토큰·비용을 추출해
  eval/results/baseline_r1.jsonl 형식(CLAUDE.md 참고)으로 저장
- --model은 CLAUDE.md의 고정 모델 사용
```

실행 전에 만들어진 스크립트를 검수합니다.
- 허용 도구가 Read 하나인가
- `--model`이 CLAUDE.md의 고정 모델인가

검수가 끝나면 1회차를 실행합니다. 2회차는 2-1에서 채점 편차를 보는 데 쓰므로, 다음 시간 중에 백그라운드로 실행해 둡니다.

### Claude Code를 쓸 수 없을 때: Claude 데스크톱 앱으로 하기

Claude Code 설치나 로그인이 안 되는 PC에서는 Claude 데스크톱 앱에 프롬프트를 직접 넣어 같은 방식(규정집 전체를 넣고 답하게 하기)을 확인합니다.

**실습 ①은 데스크톱 앱으로 그대로 할 수 있습니다.**

1. 데스크톱 앱에서 새 대화를 엽니다. 모델 선택에 Haiku가 있으면 Haiku를 고릅니다(실습의 고정 모델과 같게).
2. 저장소 루트의 `data/regs_all.md`를 대화창에 끌어다 놓아 첨부합니다.
3. 아래 프롬프트를 입력합니다.

```text
첨부한 regs_all.md 전체를 읽고, 그 내용만 근거로 다음 질문에 답해줘.
답에는 문서명·조항·시행일을 인용해.
질문: 시세 전송 지연 시 참가사 통보 기준은?
```

확인할 것: 답에 문서명, 조항, 시행일이 붙었는가. (첨부한 파일이 하나뿐이라 "다른 파일은 열지 마"는 뺐습니다.)

**실습 ②(30건 일괄 실행)는 데스크톱 앱으로 할 수 없습니다.** 앱은 질문을 자동으로 돌리거나 질문당 토큰과 비용을 파일로 남기지 못합니다. 대신 이렇게 합니다.

- 평가셋(`eval/questions.jsonl`)에서 질문 2~3건을 골라 같은 방법으로 물어봅니다. 질문마다 **새 대화**를 열고 파일을 다시 첨부합니다. 한 대화에서 이어 물으면 앞 답이 섞여 조건이 달라집니다.
- 결과 파일은 강사가 돌린 것을 씁니다: `solutions/1027/1-1/results/baseline_r1.jsonl`(2회차는 `baseline_r2.jsonl`)을 루트의 `eval/results/`로 복사합니다. 2-1 이후의 비교는 이 파일로 합니다.
- 아래 "작성할 것" 표는 그 결과 파일의 값으로 채웁니다. 질문마다 규정집 전체(약 6만 토큰)를 다시 읽기 때문에 질문당 입력 토큰이 크다는 점을 확인하는 것이 이 시간의 요점입니다.
- 6만 토큰짜리 파일을 질문마다 첨부하므로 구독 사용량이 빨리 줄어듭니다. 질문은 몇 건만 합니다.
