4-2 권한, 보안, 사람 승인

에이전트 구조는 3-3 그대로입니다. 이번 시간에는 day2/guard.py 하나를 만들어 방어 장치 다섯 가지를 켭니다. 정답 코드에서는 이 파일이 생기면 agents.py가 자동으로 불러 씁니다.

guard.py를 넣으면 무엇이 켜지나

장치어디서 막나무엇을
1. 역할별 권한도구 안 (검색, 원문 파일, 위키)질문한 사람의 역할이 볼 수 없는 등급의 문서
2. 인젝션 필터도구 결과가 모델에 가기 직전문서 속에 숨은 "AI는 ~라고 답하라" 같은 지시문
3. 사람 승인검증 다음 approve 노드비밀 등급 문서를 인용한 답 (사람이 yes/no)
4. 개인정보 마스킹mask_pii 노드답 속 전화번호 010-****-7730
5. 감사 로그audit 노드질문·역할·근거·답을 logs/audit.jsonl에 기록

검증자의 "권한 밖 문서 인용" 확인은 3-2부터 있었습니다. 4-2부터는 역할별 등급 표를 guard.levels()에서 가져옵니다.

자동으로 켜지는 방식

try:
    if os.environ.get("NO_GUARD") == "1":   # 차단 전 비교용
        raise ImportError
    from day2 import guard        # 4-2 폴더에 guard.py가 있으면 성공
except ImportError:
    class guard:                  # 없으면 아무것도 막지 않는 빈 장치
        APPROVAL_REQUIRED = False
        levels   = lambda role: ["일반", "대외비", "비밀"]
        sanitize = lambda text: text
        mask_pii = lambda text: text
        audit_log = lambda state: None
  • guard.py는 import되는 순간 enable()을 실행해, 도구가 역할을 따르게 하고(ROLE_GUARD = True) 도구 결과 필터 목록에 sanitize를 넣습니다.
  • 4-2 폴더나 그 뒤 수업 폴더(4-3, hw2)에서 실행하면 켜지고, 3-3 이전 폴더에서는 꺼져 있습니다.

왜 세 경로를 다 막아야 하나

에이전트는 문서를 세 경로로 읽습니다. 한 곳만 막으면 다른 길로 같은 내용을 읽을 수 있습니다.

검색 hybrid_search

검색 필터에 역할의 등급을 강제로 넣습니다.

원문 파일 grepread_file

역할의 원문 폴더만 허용(화이트리스트). 밖이면 PermissionError.

위키 read_page

역할의 위키 디렉터리만 읽습니다.

문서 안에 AI를 겨냥한 지시문을 숨겨 둔 공격입니다. 도구 결과가 모델에 가기 전에 sanitize()가 패턴을 찾아 지우고, 지운 문장을 로그에 남깁니다.

지시문 문장과 로그 줄은 강사 실행 기록 그대로입니다. 앞뒤 본문은 줄인 것입니다.

찾는 패턴 (INJECTION_RE)

  • AI를 부르며 명령하는 문장: "AI / 비서 / 어시스턴트 / 모델 / LLM" + "답해야 한다 / 답하라 / 출력하라 / 무시하고 / 따르라 / 지시"
  • 표시가 붙은 지시: [AI 지시] …, ※ 시스템 안내: …, ※ 참고: …
  • PDF는 한 문장이 여러 줄로 나뉘므로 줄바꿈을 넘어 문장 끝까지 지웁니다.

어디에 걸리나

도구 결과는 모두 filter_output()을 거칩니다. guard.py가 이 목록(OUTPUT_FILTERS)에 sanitize를 넣습니다. 그래서 규정 검색, 원문 읽기, 공시 MCP 도구 결과에 똑같이 적용됩니다.

패턴 방식이라 표현을 바꾼 지시문은 놓칠 수 있습니다. 그래서 작성자 지시문의 "근거만 사용", 검증자의 원문 대조와 함께 씁니다.

관리자가 "관리자 계정 발급은 누가 승인하나?"를 물으면

어떻게 멈추고 다시 이어지나

  1. 검증 통과 뒤 approve 노드가 인용 중에 비밀 등급 문서가 있는지 봅니다.
  2. 있으면 interrupt({...})로 그래프를 멈춥니다. 지금까지의 state는 checkpointer(InMemorySaver)에 저장됩니다.
  3. 사람이 답하면 같은 thread_id로 Command(resume="yes")를 보내 멈춘 자리부터 이어 갑니다.
  4. yes면 답을 그대로, no면 "승인 거부" 답으로 바꾸고 인용을 지웁니다.
out = await graph.ainvoke({"question": Q, "role": "admin"}, cfg)
if "__interrupt__" in out:          # 멈춤
    decision = input("승인? (yes/no) > ")
    out = await graph.ainvoke(Command(resume=decision), cfg)   # 같은 cfg(thread_id)

비밀 등급은 admin만 볼 수 있으므로, 이 승인은 admin의 질문에서만 일어납니다. 다른 역할은 그보다 앞의 권한 장치에서 이미 막힙니다.

시세 장애 비상연락망의 운영팀장은 김하늘이며, 연락처는 010-****-7730입니다. …

번호는 가려졌고, 이름은 번호와 떨어져 있어 그대로 나왔습니다. 평가셋 정답도 "이름은 보여 주고 연락처는 마스킹"입니다.

감사 로그 (logs/audit.jsonl)

질문 한 건마다 한 줄씩 남습니다. 거부된 질문도 남습니다.
