A. CLI 스크립트 방식

셸 실행 도구 run_shell(command)

day2/compare_cli_mcp.py 안
  • 에이전트가 명령 문자열을 만들어 넘기면 새 프로세스로 실행하고 출력(JSON)을 돌려줍니다.
  • 사용법은 시스템 프롬프트에 글로 적어 줍니다(CLI_USAGE).
  • 도구 정의는 "명령 하나 받기"뿐이라 짧습니다.
  • 셸은 어떤 명령이든 실행할 수 있으므로, python day2/dart_cli.py로 시작하는 명령만 허용합니다.

B. MCP 서버 방식

MCP 서버 FastMCP("dart") 실습 ①

day2/dart_mcp.py
  • 도구 2개: search_disclosures, get_disclosure_document
  • 함수의 설명문(docstring)이 도구 설명, 타입 표시가 입력 스키마가 됩니다.
  • stdio(표준 입출력)로 클라이언트와 대화합니다.
↕stdio로 연결, 도구 목록을 서버에 물어서 받아 옴

MCP 클라이언트 mcp_tools()

day2/compare_cli_mcp.py 안
langchain-mcp-adapters의 MultiServerMCPClient가 서버를 띄우고, 서버의 도구를 LangChain 도구로 바꿔 줍니다.

공용 에이전트 루프 build_tool_agent(tools, system) 실습 ②

src/agent_loop.py · 3-2 이후에도 같이 씁니다
START→ agent⇄ tools(최대 6회)→ END
  • agent: LLM(Haiku 5.5)이 질문과 도구 정의를 보고 도구를 부를지, 답을 낼지 정합니다.
  • tools: 고른 도구를 실행하고 결과를 대화에 붙입니다. 결과는 출력 필터(src/tools.py의 filter_output, 2-3)를 거칩니다.
  • 도구 호출마다 도구 이름, 인자, 결과 길이, 오류 여부를 tool_log에 남깁니다. 비교표의 "도구 호출 수", "인자 오류 수"가 여기서 나옵니다.
  • A와 B는 이 루프에 넣는 도구 목록과 시스템 프롬프트만 다릅니다.

A와 B는 어디가 다른가

항목A. CLI 스크립트B. MCP 서버
에이전트가 아는 방법시스템 프롬프트에 적은 사용법(글)서버가 알려 주는 도구 설명과 입력 스키마
도구 수1개(셸 명령 실행)2개(기능마다 하나)
인자 확인명령 문자열이라 형식 오류를 실행 후에야 알 수 있음입력 스키마로 이름과 타입이 정해져 있음
재사용성이 에이전트 코드 안에서만 씀다른 MCP 앱(Claude Desktop 등)에 그대로 연결
권한 범위셸이라 어떤 명령이든 가능 → 허용 명령을 직접 막아야 함서버가 내보낸 도구 2개만 호출 가능
